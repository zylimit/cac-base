# 人读工程文档说明正反范例（脱敏合成示例）

以下以虚构的「图书馆借阅系统」演示合格口吻与详略，实际编写时严禁照抄示例业务词。

## 正面范例

```text
## table:loans
一次图书借出记录：一行代表一位读者借走一册实体书直至归还的全周期。

读者在柜台或自助机借书时由借阅接口写入，`due_at` 按读者等级借期算出；续借只更新 `due_at` 与 `renew_count`，归还时回填 `returned_at`，历史行永不物理删除。逾期罚金存放在 `fines` 表，按 `loan_id` 关联。
最易看错点：本表无 status 列，`returned_at` 与 `lost_at` 同时为空才表示「当前在借」。

## column:loans.channel
借出渠道枚举：`desk` 人工柜台、`kiosk` 自助借还机、`app` 线上预约到馆取书（定义见 `lending/channels.ts` 的 `LOAN_CHANNELS`）。

## module:lending
读者借书、续借与归还流转：管理一册书从离架到回架的核心业务闭环。

管辖边界到归还入库为止——逾期金额核算归「罚金与报损」模块，本模块仅在归还时传入逾期天数。主入口为 `POST /api/loans`，先调「读者账户」校验欠费，再原子写入 `loans` 并更新馆藏册状态。修改借期算法 `due_rules.ts` 时须同步核对「统计报表」模块的逾期口径。
```

## 反面禁区（`note put` 与审查必打回）

| 错误写法 | 问题所在 | 正确做法 |
|---|---|---|
| `due_at`：到期时间。 | 纯翻译列名，零增量信息 | 写明何时由哪条规则算出、过期触发什么后果 |
| 二期为支持自助机新增了 `channel` 列。 | 写开发演进史而非现行语义 | 直接写当前各枚举值含义与定义位置 |
| 该表应该是用来存借阅流水的。 | 含「应该/大概」，未读写入源码 | 精读写入代码后确定下笔；真无法查证写 `待确认：...` |
| 例：王五在海淀分馆借了编号 10.23.4.5 的终端。 | 含真实姓名或内网 IP 形态敏感串 | 一律用明显合成的假名（如「读者甲」「示例册 A」） |
| 包含 `a.ts`、`b.ts` 共 3 个文件 5 个接口。 | 复述页面已机械生成的清单 | 写把这些文件串起来的业务职责与上下游边界 |
