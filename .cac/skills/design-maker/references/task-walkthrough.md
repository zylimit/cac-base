# 带业务目标的原型任务试走规程

与 `ui-audit.mjs`（DOM 渲染结构审计）互补：检验「人带着真实任务目标能不能顺畅走完并从错误中恢复」。

## 1. 试走方法
1. 从 `Product-Spec.md` 关键流程取 1–2 个真实目标（如「找出型号匹配的空闲维修工完成派单，并处理一次提交超时未知态」）。
2. 有真实用户参与时不预先提示「点哪个按钮」，观察其能否一眼认出入口、看懂状态反馈；无真实参与者时由 Agent 按业务视角逐步走查，并在报告中诚实标注「Agent 自演自检」（严禁编造用户满意度打分）。
3. 至少触发一次异常分支（必填漏填、并发冲突、超时结果待查或无权限），核对已填草稿是否保留、下一步恢复入口是否清晰。

## 2. 发现问题的归口回填
- 视觉主次、状态文案或布局遮挡 → 回填 `Design-Brief.md` / `demo/design-plan.md` 并修原型；
- 业务规则缺失、权限冲突或成功口径分歧 → 回流 `/product-spec-builder` 迭代模式更新 Spec；
- 跨模块事实归属或异步一致性缺口 → 交主 Agent 同步 `Architecture-Design.md` / `DFX-Spec.md`。
