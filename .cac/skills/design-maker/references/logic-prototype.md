# 离线业务逻辑沙盘构造法（单文件回答一个规则问题）

当需要让业务方亲手触发事件检验状态流转、并发先后顺序或异常恢复，而无需整套产品页面与品牌视觉时读取本参考。默认产出 `demo/logic-<问题简名>.html`（不覆盖全稿 `demo/index.html`）。

## 1. 先限定单一业务问题
在页面顶部显式展示：
- **待检验问题**：「操作者触发什么事件序列时，核心对象与派生状态应呈现什么结果」；
- **规则来源与未决分支**：注明哪些转移来自 `Product-Spec.md` 已确认规则，哪些属于待拍板候选分支；
- **模拟边界说明**：纯内存状态流转，不触发任何外部真实写操作。

## 2. 纯函数状态机 + 自由事件触发 + 一键重置
1. 代码组织分离：`initialState()` → `transition(state, event)` → `render(state)`，全部 CSS/JS 内联、零外部依赖。
2. 提供正常动作、超时结果未知、并发/迟到响应、部分失败（如主单保存成功但通知失败）及越权被拒按钮，允许按任意顺序重复点击验证幂等与边界。
3. 提供独立的 **「重置演示到初始态」** 按钮（与业务上的「取消/冲正」按钮严格分开，业务取消须按规则保留历史记录）。
4. 若需对沙盘单独运行 `ui-audit.mjs`，将其放入独立子目录命名为 `index.html` 后执行；本机无浏览器引擎退 `rc 3` 时如实注明「UI 渲染审计缺席」。
