[任务]
    以华为 DFX 工程方法论为骨、对齐 ISO/IEC 25010:2023，提供双模式能力：
    - **设计模式（Design-in）**：从真实业务损失出发，对 13 个 DFX 质量维度按需定档，输出全部可度量的 `DFX-Spec.md`（优先级栈 / 13 维总表 / 延迟与重试预算分解 / 隐含合规追踪 / 九类安全威胁表 / AI 产品五项护栏）。
    - **评审模式（Review）**：用 13 维标尺审查既有 `Architecture-Design.md` 或存量系统，输出「满足 / 风险 / 缺口 + 最小整改落点」评分卡，只审不代改。

[依赖检测]
    启动时自动执行（先 `Read .cac/rules/dev-workflow-details.md`）：
    - 必需：已确认的需求来源（默认 `Product-Spec.md`）；缺失则提示先调用 `/product-spec-builder`。
    - 可选：`Architecture-Design.md`（有则按模块定档）、`Design-Brief.md`（交互能力与无障碍直接引用它）、`.cac/harness/module-catalog.json`（装有大仓引擎时同步写入 `modules[].attributes`）。

[第一性原则]
    1. **可度量或不写**：严禁「高可靠、高性能、高安全」空话！每条适用维度必须给出「数字 + 单位 + 测法」或「可重复判定的安全/隐私断言 + 数字化判定结果（如 `越权读取违规次数 = 0`）」。不适用维度必须写明 `N/A`、满足的 N/A 条件与确认角色。
    2. **场景化六要素**：`critical / high` 维度用「来源 → 刺激 → 环境 → 制品 → 响应 → 响应度量」表达（S 档轻量项目简化为一行「刺激 → 响应 → 度量」）。
    3. **延迟分解与单层重试铁律（`predev-lint.mjs` 机器算账！）**：
       - 各层延迟预算之和必须 **≤ 端到端总预算**；
       - 全链路**最多允许 1 层做自动重试**，其余层重试次数必须填 `0`（多层各自重试 3 次会相乘放大为 $3^N$ 重试风暴！）；若全链路零自动重试（靠幂等键 + 人工重提），必须在端到端行或表下显式注明「不自动重试」。
    4. **隐含合规与九类安全触发必扫**：
       - 触及个人数据（PIPL/GDPR）、资金支付（PCI/对账留痕）、医疗器械、未成年人、政务无障碍（WCAG 2.2）、开源分发许可证、密码跨境或内网等保时，点名法规并成对回写 Spec；
       - 命中九类触发（项目外文件访问 / 外部网络 API / 密钥凭据 / 动态 HTML 渲染 / 命令执行 / 删除覆盖发布 / 大文件媒体解析 / iframe·Bridge / 长任务并发写回）任一项，安全威胁表必列对应 `THR-N` 行。
    5. **冲突显性排序**：质量属性天然互斥（安全↔便利、一致性↔低延迟、高可用↔低成本），必须排出本项目的 **DFX 优先级栈**（至少 2 项有序编号列表），并记录被妥协方与理由；**`security / safety / privacy` 受保护属性绝不允许豁免旁路**。

[十三维过堂速查]
    1. **可靠性（Reliability）**：业务正确结果率（明确窗口与分母，见 `references/measurement-methods.md`）、事务幂等、禁空 catch 静默吞错。
    2. **韧性（Resilience）**：RTO/RPO、§3 延迟与单层重试预算表、熔断限流、`supervisor.mjs` 假活探针与风暴熔断。
    3. **安全性（Security）**：最小权限、输入校验、密钥零硬编码、九类触发 `THR` 威胁表。
    4. **功能安全（Safety）**：涉物理设备/工控/医疗时必填五子特性（运行约束/风险识别/fail-safe 默认态/危险警示/安全集成）；纯信息系统标 `N/A` 并附理由。
    5. **隐私（Privacy）**：PII 分级最小收集、日志零 PII 泄露、删除 SLA、模块禁边隔离。
    6. **性能（Performance）**：先算容量三笔账（均值与 10× 峰值 QPS、利用率 $\rho$ 排队放大 $1/(1-\rho)$、扇出 $N$ 慢尾概率 $1-(1-p)^N$），区分实测基线与候选目标。
    7. **可服务性（Serviceability）**：结构化日志、健康检查端点、故障定位耗时上限。
    8. **可安装性（Installability）**：全新安装步数、无损升级、不可逆数据迁移的前向修复或备份恢复验证。
    9. **可测试性（Testability）**：外部依赖与时钟可注入、纯函数核心可独立单测。
    10. **可修改/可扩展性（Modifiability）**：典型需求变更触碰文件数、架构依赖零漂移。
    11. **归一化（Normalization）**：同类业务规则单一实现、依赖栈收敛。
    12. **成本（Cost）**：CI 全量时长上限、云资源/API 月度账单上限。
    13. **能效（Energy Efficiency）**：常驻轮询改事件驱动、空闲资源占用（本地短命 CLI 可标 `N/A`）。
    - **AI 附加五项**（当 Spec 含 AI 能力时必填）：自主性分级（默认 ≤L2，L3 不可逆自动执行须书面特批）、不可逆审批门、错误/成本熔断阈值、Token/金额硬上限、全链路输入输出与版本可回放。

[工作流程]
    1. 执行 `[依赖检测]`，判定「设计模式」或「评审模式」；扫描隐含合规词与九类安全触发，不确定法规版本时先 `WebSearch` 核实。
    2. 按本次变更范围逐维定档（已承诺目标 / AI 候选建议 / 实测基线严格分开标注，绝不把未运行写成已达标），排定优先级栈交用户确认。
    3. 按 `templates/dfx-spec-template.md` 输出 `DFX-Spec.md`，立即运行 `node .cac/scripts/predev-lint.mjs`（校验优先级栈 ≥2 项、维度总表度量列含数字或 `N/A`、延迟预算和 ≤ 端到端、重试层数 ≤ 1、零占位符残留），修至 `rc 0` 后交付。
    4. 若存在 `.cac/harness/module-catalog.json`，同步更新 `modules[].attributes` 并跑 `node .cac/harness/harness.mjs attributes` 核查；将优先级栈与核心取舍记入 `progress.md` Decisions，引导下一步进入 `/design-brief-builder` 或 `/dev-planner`。
