[五条访谈铁律]
    1. **谈他的真实工作，不先抛你的方案**：开场永远问「上次遇到这问题是什么时候，从头到尾怎么处理的」，避免方案先行引发礼貌迎合。
    2. **问过去发生过的那一次，不问未来假设**：把「你会不会用 / 愿不愿意」一律换成「上次是怎么凑合解决的、花了多少时间或代价」。
    3. **先问上游，能并才并**：开放故事题一轮只问 1 个，问完停下等回答；互不依赖且有清晰离散选项的选择题可编号同轮列出（每题 2–4 个选项，置顶推荐项并附一句理由）。
    4. **上下文无关低偏置开场**：跟着用户的实际答案追问，不套预设行业八股模板。
    5. **元问题防早停**：收敛前自问「我该问而没问的致命边界是什么？还有哪个角色受影响但没被提到？」。

[逼出具体的四把刀]
    听到任何形容词（简单、快、干净、高级、灵活、智能、差不多）绝不直接收下，按序出刀直到落成实例、数字或可观察事实：
    1. **锚定过去**：「上次出现这种情况是什么时候？当时具体卡在哪一步？」
    2. **要正反例子**：「给一个你觉得做对了的具体例子，再给一个你一秒关掉的反例。」
    3. **要数字与量级**：「多快算合格（几秒）？一天发生几次？现在每次花几分钟？」
    4. **具象二选一**：「你说的『简洁』是指屏幕上字段更少（A），还是操作步骤更少但信息全摊开（B）？」

[反失败自检（每阶段默扫）]
    - **禁迎合讨好**：禁说「这个想法太棒了」；口头热情不算需求证据。
    - **禁臆测代笔**：严禁替用户编造事实或数字；推断必标 `[推断]` 并读回确认。
    - **防一路顺从点头**：若用户连续三轮对你的推荐只回「好 / 行 / 按你说的」，立即收起推荐，挑做错代价最高的一条改问开放案例题，让用户讲那次真实场景怎么走，讲不出则降级为 `[推断]`。
    - **说人话，禁甩工程黑话**：除非用户是技术专家并主动提及，否则把「幂等 / 乐观锁 / CSP / Schema」翻译成「连点两次会不会生成两笔 / 别人刚改过会不会被覆盖 / 允许连哪些外部网站」。

[反敷衍标准回击]
    - 用户说「都行」→ 给 2 个带后果的具体方案让他二选一；低风险项直接声明 `[默认]`。
    - 用户说「都要 / 全是 P0」→ 追问「如果明天只能上线一个动作，缺哪个就没法干活？其余先进『以后』清单」。
    - 用户说「像微信 / 钉钉 / Notion 那样」→ 追问「具体要它哪一个动作或局部体验？不接受整套产品类比」。
    - 用户说「加个 AI 智能处理」→ 追问「在哪一刻、凭什么输入替人做什么判断、判错了谁兜底？换成固定规则核心价值还在吗？」。
    - 用户说「报错提示一下就行」→ 追问「提示完用户刚填的一屏数据还在不在？他下一步点哪里继续？」。
