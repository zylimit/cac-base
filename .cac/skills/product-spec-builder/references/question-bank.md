[使用说明]
    维度 1–4 为业务地基（必过）；5–11 按项目形态动态裁剪；12–13 仅在含 AI 能力或构建自主 Agent 系统时启用。内部编号不向用户暴露。

[1–4 · 业务地基四维]
    1. **现状故事（as-is）**：主问「上次碰到这事是什么时候？谁先动手、用什么表格或工具、最后怎么收尾？」｜驳回：「所有人都会用」「一般来说」。
    2. **受益、买单与受损者**：主问「做成了谁最先松一口气？谁反而多了一步操作或不高兴？现在每月为此损耗多少时间或钱？」｜驳回：无数字的「很慢很烦」。
    3. **规则与例外**：主问「有没有哪次破例没按这条规矩走？为什么破例、谁批的？」｜接受标准：每条规则含正例 + 例外（或明确无例外）。
    4. **拍板权与历史教训**：主问「以前试过解决吗、卡在哪？哪些既定前提绝不能动？最终谁拍板验收？」

[5–11 · 产品规格七维]
    5. **成功判据**：可数、技术无关的业务指标 + 当前基线 + 至少 1 条防副作用反向指标（禁拿注册量/点击量充当完成度）。
    6. **范围与显式非目标**：P0 最小闭环 + 至少 3 条本版明确不做的非目标 + 「以后」停车场。
    7. **关键流程与失败/未知恢复**：命名主角逐步走到高潮一拍；最易失败步骤的提示、草稿保留、超时结果未知时的查证办法。
    8. **数据归属与权限**：核心实体、单一写入者（谁能改）、可见性边界、删除/归档路径（可建必可删）。
    9. **产品形态与情境**：站坐/单双手/打断频率/光线设备 → 推导 Web / Desktop / CLI / Mobile / Agent 及首屏唯一首要动作。
    10. **非功能与隐含合规**：性能/安全/隐私/兼容/可靠/可访问六类给数字或「不要求」；涉个人数据/资金/医疗/物理控制点名法规交 DFX。
    11. **术语统一与矛盾裁定**：同物同名；冲突要求并排摆出由用户二选一记入决策依据。

[12–13 · AI 与 Agent 条件专项]
    12. **AI 能力四问**：先过 Litmus Test（换规则/搜索行不行）→ ① 质量阈值与好坏样本；② 触发（建议确认 vs 自动）；③ 绝不能做清单 + 不确定时动作 + 挂机降级；④ 延迟与单次/日成本上限。
    13. **自主 Agent 八项**：自主分级与不可逆审批门、工具权限集、上下文与跨会话记忆、单/多 Agent 编排、离线评估集与线上追踪、单任务成本熔断、死循环/卡死交还人策略、中断恢复。

[连带需求触发器（命中主动作时只挑最关键 1–2 项追问）]
    | 用户提到 | 必核连带边界 |
    |---|---|
    | 上传 / 导入 | 格式白名单、体积与条数上限、部分成功处理、落盘位置、如何删除 |
    | 画布 / 拖拽 / 时间线 | 选择模型、撤销栈、自动保存、误触恢复、键盘可替代路径 |
    | 长耗时任务 / 导出 | 任务 ID、进度展示、中途取消、关页重开找回、防重复提交 |
    | 外部 API / 联网 | 密钥存放、允许域名范围、出境数据边界、超时与限流降级 |
    | 删除 / 覆盖 / 外发 / 扣款 | 二次确认或撤销窗口、变更预览、备份、审计留痕 |
