[生成前必过七项自检]
    1. **地基完整**：产品概述写清了为什么做、受益/买单/受损三类人并有真实案例支撑；应用场景含真实人物顺序故事与单独例外段。
    2. **零模糊形容词**：正文中无「快、直观、智能、合理、适当、友好提示」等不可判定空话，全部已转化为数字、具体例子或可观察状态。
    3. **完整结果链**：核心功能均为「用户做什么 → 系统做什么 → 得到什么」；关键流程含高潮一拍及失败/超时未知态的数据保留与下一步恢复；可建资源均有删除/归档路径。
    4. **范围硬边界**：至少 3 条显式「非目标」，且与「以后」停车场区分清楚。
    5. **标记与待定表合规**：功能条目 100% 带 `[确认]` / `[推断]` / `[默认]`，**零 `[待定]`**；「待定问题」表每行五格齐全（问题 / 影响什么 / 谁能答 / 押后到 / 不答先按什么做），全文无 `{{...}}`、`<...>`、`TBD`、`TODO`、`待补` 残留。
    6. **可度量判据**：成功判据至少 1 行真实数据且含基线与反向指标；非功能六类与隐含合规已逐项表态。
    7. **下游可接手**：`arch-designer` 能直接提取实体单一写入者与故障后果，`design-brief-builder` 能直接提取使用情境与首要动作，主 Agent 派单能直接抄出 `Business Context`。
