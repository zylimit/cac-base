# 从验收证据反推 Task 切片、依赖边界与大范围迁移

排布跨模块依赖、待取证口径或破坏性接口迁移计划时读取本参考。

## 1. 从客观证据反推四件事
对每条验收标准先追问：
1. **在哪观察真实结果**：CLI 退出码与 JSON 输出、持久化重读、页面 DOM 状态，绝不用「编译通过」替代业务结果。
2. **谁负责最后一公里接线**：接口与前端各自有 Task 时，明确哪一个 Task 负责端到端联调闭环。
3. **谁产生独立证据**：对齐 `.cac/rules/dev-workflow-details.md` 的 LOW / MEDIUM / HIGH 定档，作者自测不能替代 HIGH 档独立 `tester`。
4. **功能前置 vs 验证前置分离**：共享 Schema/基础类型为「功能前置」（进拓扑序卡开工）；外部联调环境为「验证前置」（mock 可先开发，但未接真接口前不得宣称集成验收完成）。

## 2. 口径未定时的取证依赖排法
若关键计算口径（如分子分母定义）尚待业务拍板、无法写出确定预期值，严禁拍脑袋编造 expected 塞进编码 Task——先单列「取证/澄清前置项（谁回答什么 → 解锁哪个 Task）」，不依赖该口径的已知 Task 照常推进。

## 3. 多消费者兼容迁移三步序
当公共函数签名、配置结构或表字段需跨多调用方变更时，按 **「提供新契约并保留旧兼容层 → 分批迁移全部调用方与生成器 → 确认旧引用清零且全量测试绿后移除旧兼容层」** 拆 Task，写明每批失败时可退回的已知绿灯基线。
