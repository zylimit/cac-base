# 用一条业务路径与异常断点检验模块边界

当涉及跨职责写入、外部调用结果不确定或存量迁移时读取本参考。

## 1. 从业务事件与事实归属划边界
1. 先用业务语言连成协作线：`发起人触发事件 → 规则校验 → 权威事实落库（Single Writer） → 派生动作/外部通知`。
2. 部门、前端页面或物理表不天然等于模块；职责边界看「**哪两件事的失败后果不同、变化原因不同**」（例如「外部通知发送失败」绝不能回滚「已成立的核心业务单据」）。
3. 同进程内清晰分包即可守住边界时，不默认拆微服务或引入重型消息中间件。

## 2. 在四个典型断点上追演候选方案
用同一个中断场景拷问所有候选方案：
1. **响应丢失与重试**：服务端已提交但客户端超时未收到响应，用户再次提交时如何识别同一业务意图（幂等键作用域）而不重复扣减/重复创建？
2. **复合动作半途中断**：核心事实已提交、派生动作尚未发出时进程重启，待办义务是否随同一事务持久化可找回？
3. **外部副作用结果未知**：外部接口实际已执行但本地未记下完成就中断，恢复后如何查证或人工兜底（区分「结果未知」「已拒绝」「已完成」，未经证实不承诺恰好一次）？
4. **更正与历史保留**：撤销、修改与追加冲正具有不同业务语义，不笼统混称 `rollback`。
