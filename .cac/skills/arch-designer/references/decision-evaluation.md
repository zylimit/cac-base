# 同场景候选对比、敏感假设与状态冲突追演

当存在多个实质性架构候选、跨属性权衡或异步编辑冲突时读取本参考。

## 1. 同场景公平比较候选
避免给推荐方案写完整异常处理、却给备选方案只写粗糙草图：

| 候选方案 | 同一正常与故障断点下的表现 | 守住/牺牲哪条不变量 | 运维与迁移代价 | 证据状态（实现事实/纸面推演/实测） |
|---|---|---|---|---|
| 现状或最小方案 | ... | ... | ... | ... |
| 候选方案 B | ... | ... | ... | ... |

评估是否保留某个中间抽象/Facade 层时，对比「调用方前置知识是否真减少、是否集中承担了鉴权/事务/兼容职责」——纯原样透传且无实质职责的包装层优先精简。

## 2. 敏感假设与推翻条件（Falsification）
对关键推荐写明：「**如果实测观察到 X，则推翻或收窄本方案**」，并指明最小验证手段（契约核查 / 隔离故障注入 / 逻辑沙盘 `/design-maker` / 基准抽测）。未实跑前状态只能标「拟验证」，严禁预填 PASS。

## 3. 异步返回撞上用户新编辑的时间线核对
1. 用户提交对象 A 的草稿 v7（发出请求 Q1），等待期间将 A 改为 v8 或切到对象 B。
2. Q1 返回成功时，只能确认 v7 快照已处理，严禁静默覆盖用户正在编辑的 v8 或把 v8 谎报为已保存。
3. 明确五类状态的归属边界：业务权威事实 / 临时 UI 草稿 / 视图偏好 / 请求任务代次 / 外部文件资产。
