# 按故障症状选择最短可证伪诊断回路

当遇到仅特定环境复现、偶发时序竞态、性能退化或已修一轮仍失败的疑难缺陷时读取本参考。

| 症状特征 | 最短触达回路 | 必备客观证据 |
|---|---|---|
| **已有失败用例或必现命令** | 直接运行原失败用例，必要时构造最小 CLI/函数输入复现 | 保留原始输入、失败断言行与非零退出码；修完必回原用例复验 |
| **特定请求或事件序列后触发** | 脱敏录制输入序列，固定初始状态、权限身份与调用次序重放 | 确认重放真正走过同一业务分支，而非被前置鉴权拦截 |
| **仅某平台/版本/配置出现（如仅 Windows 报错）** | 固定同一输入，单变量对比路径分隔符、CRLF、编码、环境变量或版本二分 | 每次只变一个变量，记录首个分歧点并解释底层机制（如 `shell: false` vs `.cmd`） |
| **偶发、并发抢占或异步乱序** | 使用可控 Promise 屏障、假时钟或事件队列强行固定乱序到达顺序 | 在固定时序下让红锁测试 100% 稳定变红（严禁靠循环跑 100 次碰运气） |
| **性能退化或假死空转** | 固定数据量与测量起止点，检查 CPU 占用（0% 多为死锁/等待，100% 多为死循环或正则回溯） | 记录修复前后同规模耗时对比，严禁仅靠调大 timeout 掩盖问题 |
