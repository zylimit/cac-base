# 复杂模块设计详述规范（design-detail）

> 本文件由 `AGENTS.md` 下沉；读、写、核对 `docs/design/*.md` 或派单触及其代码范围前必须完整 `Read` 本文件。

## 1. 定位与启用条件

- **设计详述**记录某个复杂模块内部的算法与业务规则到底怎么算：阈值、先后顺序、例外、取代关系，每条规则绑定代码位置、常量与测试。
- **存在即维护，简单模块不强制**：存放在 `docs/design/<模块名>-设计.md`。同一模块的业务规则一周内反复改动 ≥2 次，或规则数 >5 条，即应建立设计详述。

## 2. 固定五段文档结构（供 `design-trace.mjs` 与 `three-file-sync-gate` 机器解析）

模板见 `.cac/skills/arch-designer/templates/design-detail-template.md`，段名不可更改：

1. **文首代码范围声明**：`> 代码范围：` 后跟反引号包裹的相对路径或 glob（逗号分隔，如 `` `src/pricing/**`, `src/tax.ts` ``）。`three-file-sync-gate` 的 `design-detail-sync` 子闸据此判定代码改动是否落入范围。
2. `## 1. 概述`：输入、输出、一句话主流程。
3. `## 2. 规则`：按执行顺序分节，每条现行规则一个四级标题 `#### <编号> <一句话标题>`（编号格式 `<模块缩写>-<步骤缩写>-<两位序号>`，如 `PR-TAX-01`，发出后永不复用）。每条必填六项：
   - **规则**：一句话精确判据，禁「大概/尽量/通常」；涉及数字一律写常量名，禁止裸数字。
   - **来源**：谁、哪天、原话或实测依据（或引 `domain/` 口径编号）。
   - **例子**：输入 → 输出（必须用合成脱敏数据，严禁真实生产敏感数据）。
   - **代码**：`文件路径:函数名`。
   - **常量**：用到的常量名（无数字填「无」）。
   - **测试**：对应测试名（未补填「待补」，`design-trace.mjs` 会报缺口）。
4. `## 3. 常量表`：表头固定 `| 常量名 | 值 | 代码位置 | 含义 | 用于 |`。
5. `## 4. 已知例外与坑` 与 `## 5. 取代记录`（被取代的旧规则搬入第 5 节，标题追加 `→ 被 YYYY-MM-DD <新编号> 取代`，不删除）。

## 3. 机器核对与流程接线

- 测试用例中用注释标注所验证的规则编号：JS/TS `// rule: PR-TAX-01`，Python/Shell/PS1 `# rule: PR-TAX-01`（多条逗号分隔）。
- 运行 `node .cac/scripts/design-trace.mjs [--root <dir>] [--json]` 双向核对四类缺口：① 有规则无测试标签；② 测试标了不存在/已取代编号；③ 常量表的值与代码定义不一致或不唯一；④ 文档结构或代码范围通配匹配 0 文件。退出码：`0`=全过或无设计详述，`1`=有缺口，`2`=参数错，`3`=内部异常。
- **派单与审查联动**：触及设计详述代码范围时，派单 `Business Context` 必抄相关规则；`implementer` 回执 `Design rules` 必填改了哪条或「规则未动」；`Stop` 时改了范围内代码而未同步设计详述由 `design-detail-sync` 提醒（`strict` 档硬拦）。
